# Part 8.1a — แก้ไขรายการงบและวัน/เวลาจ่ายจริง

แพ็กเกจนี้แก้เฉพาะ Part 8.1a ของเว็บเที่ยวไทย 77 จังหวัด โดยใช้ไฟล์ต้นฉบับที่ได้รับมา ไม่รวมงานลบ/ล้างยอดพร้อม Undo (Part 8.1b) และไม่รวมการแทนที่รายการประมาณการแบบ atomic (Part 8.1c)

## สิ่งที่เปลี่ยน

- แต่ละแถวรายการมีปุ่ม **“แก้ไข”** พร้อมไอคอนที่เห็นชัดและกดได้สูงอย่างน้อย 44px
- ฟอร์มแก้ไขรองรับ **วันที่และเวลาที่จ่ายจริง** (`spent_at`) และแสดงวัน/เวลาในแถวรายการ
- จำนวนเงินต้องไม่ติดลบ มีทศนิยมได้ไม่เกิน 2 ตำแหน่ง และรายการจ่ายจริงห้ามปล่อยยอดว่าง
- เงินทุกตำแหน่งในหน้างบแสดง 2 ตำแหน่ง เช่น `฿125.50` ไม่ปัดทิ้งสตางค์
- การเพิ่มและแก้ไขรอแถวข้อมูลที่ Supabase/PostgREST ส่งกลับ ตรวจค่าที่บันทึก แล้วจึงอัปเดตหน้าจอและแจ้ง “บันทึกแล้ว”
- เมื่อแก้รายการอัตโนมัติ ยังคงเปลี่ยนเป็นรายการแก้เอง (`is_auto: false`) ตามพฤติกรรมเดิม
- ตรรกะประมาณการ สรุปงบ การคำนวณจากแผน การหารผู้จ่าย และการยืนยันลบเดิมยังอยู่

## SQL / Migration

**ไม่ต้องรัน SQL และไม่มี Migration ใหม่** เพราะไฟล์ปัจจุบันอ่านและเขียน `budget_items.spent_at` อยู่แล้ว และงานนี้ไม่ต้องเปลี่ยนตารางหรือ Policy

จากหลักฐาน Policy ที่ได้รับ: `SELECT` ใช้ `is_trip_member(trip_id)` และ `INSERT/UPDATE/DELETE` ใช้ `can_edit_trip(trip_id)` สำหรับ `authenticated` จึงไม่เปลี่ยน RLS ใน Part นี้ อย่างไรก็ตาม ยังไม่ได้ตรวจเนื้อหาฟังก์ชันทั้งสองหรือรันทดสอบสิทธิ์จริง

## ติดตั้งผ่าน GitHub บนเบราว์เซอร์

1. ดาวน์โหลด ZIP แล้วแตกไฟล์บนคอมพิวเตอร์
2. เปิด Repository `thai77` บน GitHub และตรวจว่าอยู่ Branch ที่ต้องการ (แนะนำสร้าง Branch ใหม่ เช่น `part-8-1a-budget-edit`)
3. ไปที่ `src/pages` → **Add file → Upload files** → อัปโหลด `BudgetPage.tsx` จาก ZIP แล้ว Commit
4. ไปที่ `src/features/budget` → **Add file → Upload files** → อัปโหลดไฟล์ต่อไปนี้พร้อมกัน แล้ว Commit:
   - `BudgetItemSheet.tsx`
   - `budgetApi.ts`
   - `calc.ts`
   - `part8_1a.test.ts`
   - `budgetApi.part8_1a.test.ts`
5. ตรวจแท็บ **Files changed** ให้มีเฉพาะ 6 ไฟล์ด้านบน
6. เปิด Pull Request เข้า `main` หากมี GitHub Actions เดิม ให้รอ TypeScript, Unit และ e2e เดิมผ่านก่อน Merge
7. หลัง Merge รอ GitHub Pages deploy แล้วกดรีเฟรชแบบไม่ใช้แคช (`Ctrl+Shift+R`)

## วิธีทดสอบบนเว็บและผลที่ควรได้

### 1) เพิ่มรายการจ่ายจริง

1. เปิดทริป → งบประมาณ → **บันทึกจ่ายจริง**
2. กรอก `125.50` เลือกหมวด ป้ายกำกับ ผู้จ่าย และวัน/เวลาจ่าย
3. กดบันทึก

ผลที่ควรได้:
- ปิดฟอร์มหลัง API ตอบกลับและตรวจแถวที่บันทึกสำเร็จแล้วเท่านั้น
- แถวรายการแสดง `฿125.50` และวัน/เวลาจ่าย
- สรุป “ใช้จริงแล้ว”, “คงเหลือ”, “หารต่อคน” อัปเดตทันที

### 2) แก้ไขรายการ

1. ในแท็บ **รายวัน** หรือ **รายการ** กดปุ่ม **แก้ไข** ของรายการ
2. เปลี่ยนยอดเป็น `120.25` เปลี่ยนหมวด ป้ายกำกับ ผู้จ่าย บันทึก และวัน/เวลา
3. กดบันทึกและเปิดรายการซ้ำ

ผลที่ควรได้:
- ค่าทุกช่องตรงกับค่าที่แก้
- แถวและสรุปแสดง `฿120.25`
- ถ้าเป็นรายการประมาณการอัตโนมัติ รายการนั้นกลายเป็นรายการแก้เองและไม่ถูกคำนวณทับตามพฤติกรรมเดิม

### 3) ตรวจ Validation

ลองทีละค่าแล้วกดบันทึก:

- `-1` → ต้องไม่บันทึก
- `1.999` → ต้องไม่บันทึก
- เว้นยอดจ่ายจริงว่าง → ต้องไม่บันทึก
- กรอกยอดจ่ายจริงแต่ไม่เลือกวัน/เวลา → ต้องไม่บันทึก
- `0` หรือ `0.00` → บันทึกได้ เพราะข้อกำหนดคือจำนวนเงิน ≥ 0

ข้อความผิดพลาดต้องอธิบายว่าห้ามติดลบ/เกิน 2 ตำแหน่ง หรือต้องเลือกวันและเวลา

### 4) Regression ของประมาณการและการสรุป

1. กด **คำนวณจากแผน** และยืนยันตามเดิม
2. ตรวจยอดประมาณการ แถบสถานะ แยกหมวด แยกรายวัน และใครจ่าย
3. แก้เฉพาะยอดจ่ายจริงหนึ่งรายการ

ผลที่ควรได้: รายการประมาณการอื่นไม่เปลี่ยน และสรุปคำนวณใหม่จากข้อมูลล่าสุด
