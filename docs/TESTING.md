## RLS Security Test
1. รัน migration 001–007 และ seed ให้ครบก่อน
2. Supabase → SQL Editor → New query → วาง `supabase/tests/rls.test.sql` ทั้งไฟล์ → Run
3. ผลจะเป็นกล่อง **ERROR** สีแดง — ตั้งใจ: สคริปต์จบด้วย `raise exception` เพื่อ Rollback ผู้ใช้/ข้อมูลทดสอบทั้งหมด ไม่ทิ้งอะไรไว้ในฐานข้อมูลจริง
4. อ่านรายงานในข้อความ: บรรทัด `PASS` = ถูกต้อง, `FAIL` = ช่องโหว่ — ท้ายสุดต้องเป็น `ALL PASSED 86/86`
5. ถ้ามี error แบบอื่น (ไม่มีรายงาน) เช่น "ยังไม่ได้รัน Migration 007" ให้ทำตามข้อความ

สิ่งที่ตรวจ (ตัวอย่าง): ผู้ใช้อื่นอ่าน/แก้/ลบทริปของเราไม่ได้, เลื่อนตัวเองเป็น Admin ไม่ได้, Editor ลบทริปหรือเปลี่ยนเจ้าของไม่ได้, Admin ไม่เห็นทริป/รูป/บันทึกลับของผู้ใช้, ผู้เยี่ยมชมแก้อะไรไม่ได้, รูปส่วนตัวเข้าถึงข้ามโฟลเดอร์ไม่ได้, ทุกตารางเปิด RLS

**ควรรันซ้ำทุกครั้งที่แก้ Policy หรือเพิ่มตาราง** (ตารางใหม่ที่ลืมเปิด RLS จะทำให้ข้อ "ทุกตารางเปิด RLS" แดง)

## ข้อจำกัดที่ต้องรู้
- Test ตรวจ **ตรรกะ** และ **นโยบาย RLS** ไม่ได้ตรวจหน้าตา UI ละเอียด (ยกเว้นชุด e2e ข้างต้น)
- ตัวจัดเส้นทางใช้ระยะเส้นตรง × ตัวคูณ ไม่ใช่ระยะถนนจริง — Test ยืนยันว่า "สอดคล้องกันภายในระบบ" ไม่ได้ยืนยันว่าตรงกับ Google Maps
- กรณีกำหนดเวลาเลิกเที่ยวตึงมาก และมีสถานที่ที่เปิดเฉพาะค่ำคืน ระบบอาจจัดให้วันนั้นเกินเวลา (แสดงคำเตือนสีแดง ไม่ซ่อน) — มี Test บันทึกพฤติกรรมนี้ไว้
- ยังไม่มี Test ต่อ Supabase จริงจากฝั่งเบราว์เซอร์ (เช่น อัปโหลดรูป, Edge Function) ต้องทดสอบด้วยมือ
